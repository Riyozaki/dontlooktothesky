## Гит-протокол (один репо, без суеты)

- **⚠️ ВРЕМЕННОЕ ПРАВИЛО (27.07, до решения автора):** `origin/main` сейчас содержит архивную версию игры (коммит `fddbf48` «Add files via upload»). До восстановления `main` автором **запрещено** выполнять `git reset --hard origin/main` — это уничтожит всю новую работу. Синхронизация только со своей веткой: `git fetch origin && git reset --hard origin/<своя ветка>`.
- `main` — единственная общая правда (после восстановления автором). Прямые пуши в `main` запрещены обоим.
- Каждый агент работает **только на своей сессийной ветке** (`arena/*`). Чужую ветку не трогать, не мержить, не перебазировать.
- Синк в начале каждого блока работы: `git fetch origin && git reset --hard origin/main` — **никаких merge локальных веток между собой**.
- Публикация: коммит → push в свою ветку → PR в `main`. Мержит PR **автор** (или второй агент по его прямому указанию), squash-мерж предпочтительно.
- **Force-push запрещён везде.** Если пуш падает на авторизации — работать локально, пушить позже, автора уведомить.
- `temp/` и `drafts/` — локальные (gitignored), не синхронизируются и не требуют PR.

## Процесс по дню (новая глава)

1. Kimi выкладывает бриф дня в `docs/story/briefs/dXX-brief.md` + запись в `from-kimi.md` «бриф dXX готов, писатель берёт в работу».
2. Arena-писатель пишет сцену, прогоняет `style_guard` + suite + gate, отмечает в `from-arena.md` «dXX черновик готов, прошу сюжетную рецензию».
3. Kimi ревьюит по канону (маршрут, сроки, движок, мотивы) — замечания в `from-kimi.md` или «ок».
4. Писатель правит/финализирует, PR в main, автор мержит.
5. Объём — по бюджету `full-story-plan.md`; меню обязательны в каждой главе и всегда замаскированы (игроку не объясняем, что выбор решает маршрут).
